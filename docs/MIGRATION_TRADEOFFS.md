# 移行で変わること・残る制限（2026-10-22）

既存の業務データと機能の維持を目的にする。以下の負担・差異を隠して「全機能復旧済み」と扱わない。本番切替と旧実機アプリ削除は未実施。

| 対象 | デメリット・できなくなること | 維持するもの・対策 | 残る検証 |
|---|---|---|---|
| Home・Stock署名変更 | 旧署名から通常の上書き更新はできない。検証後に一度再インストールが必要 | 旧アプリを残して外部暗号化バックアップ→別端末復元→件数・内容照合を先に実施。以降は同じ新鍵で更新する | 実ユーザーデータ、実機SAF操作、配布経路の試験 |
| 旧Androidアプリのバックアップ | インストール済み旧APKがdebuggableでなければ、run-as方式ではデータを読み出せない | 読出し不可時に中止。旧鍵の再利用や先行アンインストールによる回避をしない | 実機の既存APKで読出し可能か確認。不可の場合、正規のエクスポート手段を別途確立するまで移行不可 |
| Androidウィジェット・権限 | OSのウィジェットIDと配置、通知・インストール権限は自動移植できない | 旧IDごとのウォッチリストは保存。再配置後にウォッチリストを再設定し権限を再許可 | 実機の全ウィジェットの表示・操作・定期実行 |
| 認証情報 | Backendトークン、分析APIキー、Googleログインはファイルから復元できない | 秘密値の平文エクスポートを避け、再入力・再認証。ローカル業務データは復元 | 新証明書のOAuth登録と実認可。元の秘密情報を安全に確保 |
| Gmail | 現在はボタン操作で未読件数を取得。従来の通知発生件数とは意味が違い、バックグラウンドでの自動取得は未実装 | 個人画面のみ、OAuth gmail.metadataでUNREADの件数だけ取得。通知アクセス権限を復活させない。旧件数の保存データは保持 | OAuth Consoleの設定・実機認可・安全な自動取得の設計と試験。従来同等の機能復旧は未完了 |
| 夫婦共有 | 匿名・未承認アカウントや共有URLだけでのクラウド読書きはできない | 管理者が承認したGoogle UID 2人で同期。認証・通信失敗でも端末内の閲覧・編集を維持 | 現行Rulesの取得と他アプリを含む差分確認、管理者バックアップ・別環境復元、実アカウント2台試験 |
| バックアップ暗号化 | パスフレーズを紛失したファイルは復号できない | パスワード管理ツールで別保管し、元データを消す前に別環境で復元。回復用の平文コピーを作らない | 実データでの全件照合 |
| 復元後の同期 | 復元直後はクラウドへ自動送信しない。確認して同期再開が必要 | ローカル閲覧・編集は可能。復元前退避とロールバックを備える | 本番既存データとの競合確認 |
| 同じ項目の同時編集 | 同じ項目の異なる値を両方「現在値」にすることはできない | 決定的な競合解決。家計簿は履歴に変更前後を保存。移行前バックアップも保持し、競合時に内容確認 | 実データの同一項目競合・履歴確認 |
| Webオフライン起動 | 初回から完全オフライン、ブラウザの保存領域消去後、キャッシュ未完了時は起動を保証できない | 一度オンラインで読み込んだ公開アプリファイルのみService Workerでキャッシュ。業務データ・Firebase応答・認証情報は含めない。業務データはlocalStorage＋外部暗号化バックアップ | 実機ブラウザの保存領域・キャッシュ・省電力制限 |
| 破損したローカル保存 | 破損を検出した状態で通常画面から編集はできない | 初期値で上書きせず元文字列を残す。回復画面で暗号化書出し・正常なバックアップから復元できる | 破損理由の調査。原本保存を先行 |

公開済み旧署名鍵は、リポジトリから削除しても秘密には戻らない。本番端末が旧署名版のままなら移行完了とはいえない。重大問題の解消完了は、実データ保護を実証し本番の署名・アクセス制御を切り替えた後に判断する。

## 今回追加した検証

両Webアプリで、実ブラウザによる暗号化書出し→誤パスワード拒否→別ブラウザ復元→全保存値一致→ロールバック、破損JSONの原文保持→正常バックアップ復旧、ブラウザ通信遮断→再読込→編集→再読込の保持を確認した。各12件のNodeテストとFirebaseアクセスルール試験が成功。婚姻の既存同期回帰も成功。すべて合成データ・ローカルエミュレータであり、本番実データや実Googleアカウント2台の結果ではない。
